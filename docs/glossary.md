# Glossary

- **Agent** — a program driven by a language model that is given one job at a time.
- **Role** — what an agent is for: coder, verifier, QA, test-writer, examiner, auditor, Principal.
- **Examiner** — the role of the agent that reads a ticket before any work and stops it over what would have to be guessed: words with two readings, a criterion nobody could check, a contradiction, two pieces of work in one.
- **Epic** — a large piece of work agreed between the user and the Principal. It is described under three headings: its goal, what it includes and what it excludes.
- **Closed** — an epic marked complete with `dk close`; it shows as one line and takes no more tickets.
- **Ticket** — one unit of work, under three headings: what is wanted, its acceptance criteria and what is out of scope.
- **Process** — the ordered list of steps every ticket goes through.
- **Step** — one stage of the process, carried out by an agent, by the program or by the user.
- **Outcome** — how a step ended: passed, failed (the work goes back to be redone), lost (the step gave nothing usable and is done again) or stopped (the user decides).
- **Attempt** — one try at a ticket; a failed or lost outcome uses one up.
- **Stopped** — a ticket that waits at its step for the user: out of attempts, blocked, a question, or a merge that could not be done. `dk retry` sends it on.
- **Stop review** — the Principal's look at a ticket that has just stopped: it sends it on once with an answer that is safe to give (it follows from what is decided and is cheap to put right), or explains the stop to the user. Shown in the `team_forum` tab.
- **Cancelled** — a ticket given up with `dk cancel`; nobody works on it again and its unmerged work is thrown away.
- **Proposed** — a ticket an agent suggested (`dk propose`) for work nobody asked for; nothing happens to it until the user accepts it (`dk approve`) or turns it down (`dk reject`).
- **Exploring** — finding out what to build, done by the Principal in the conversation and written in `docs/discovery.md`; never a ticket.
- **Follows** — a ticket that builds on another (`--after`) and is not started until that one is merged or cancelled.
- **Vetting** — the look a reviewer takes at new behaviour tests before the user is asked to approve them (step `vet`).
- **Skipped** — a step whose role no agent has; the history records it.
- **Verdict** — a reviewer's answer: approved or rejected with what must change.
- **Brief** — the instructions an agent receives for one job.
- **Answer** — the last line of an agent's reply: done, blocked or question.
- **Copy** — a ticket's own working copy of the project (a Git worktree on branch `ticket/<n>`).
- **Checks** — the project's own commands that must succeed; run by the program, never trusted from an agent.
- **Behaviour test** — a Gherkin scenario written before the code and approved by the user.
- **Without behaviour tests** — a ticket written with `--no-behaviour-tests` because it changes nothing a user of the product can see; it starts at the coder.
- **Protected** — a behaviour-test file the user approved; the program puts it back if a coder changes it.
- **Waiting** — a ticket stopped at a step that is the user's own decision (`dk approve` / `dk reject`).
- **Audit** — a look over the whole project for security, for performance or for how well its tests protect it, asked for by the user or by the night shift; it leaves a report in `docs/audits/` and changes nothing else.
- **Night shift** — `dk night`: every kind of audit whose last report the project has changed since, then the unfinished tickets; `--at HH:MM` has the system start it every day.
- **Note** — one line a coder may add to its answer for the user (`RESULT: done: ...`); kept in the ticket's history and shown to no reviewer.
- **Auditor** — the role of the agent that carries out audits.
- **Director** — the piece that decides what happens next to each ticket.
- **Clash** — a ticket's work collides with work merged while it was in progress; the coder gets the files to resolve.
- **Board** — the view that redraws itself (`dk status --watch`, the `status` tab): what each agent is doing and the unfinished tickets.
- **Tab** — a Herdr tab that shows one agent's work as it happens; nothing typed there reaches the agent.
- **Principal** — the agent the user talks with; it explores, writes tickets and reports, and does no work on tickets itself.
- **Conversation** — a `dk talk` session; the director works behind it and stops when it ends.
- **Spent** — the tokens a job has sent to its model and the tokens the model wrote, as the agent's program reports them; every call sends again what came before, so it measures cost, not how full the model's memory is.
- **Session** — what an agent program remembers of one job, under a name of its own; with it, an agent that stopped to ask picks its job up again instead of starting afresh.
